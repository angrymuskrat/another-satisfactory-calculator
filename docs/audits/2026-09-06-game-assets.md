# Данные игровой сборки для остатка аудита

Извлечены 2026-09-06 из установленной Satisfactory: Steam build **24656030**,
CL **502094** (`rel-main-anniversary-2026`). Игра не запускалась; её файлы не
изменялись. Снимки являются компактными производными игровых данных Coffee Stain.

## Закреплённые источники

- [menu-assets.json](../../packages/game-data/source/menu-assets.json): 28 категорий
  с RU/EN локализацией, 152 связи предметов, 276 рецептов. 37 рецептов имеют
  собственный `mOverriddenCategory`; три Nobelisk наследуют категорию родителя.
- [research-assets.json](../../packages/game-data/source/research-assets.json):
  10 деревьев MAM, 110 узлов, 8 фаз Project Assembly, условия ветвей и координаты
  родителей/видимости. 13 сезонных узлов остаются справочными.
- [buildable-defaults.json](../../packages/game-data/source/buildable-defaults.json):
  общий размер слота усилителя и подтверждение его применения без override.

SHA-256 каждого снимка записан в [provenance](../../packages/game-data/source/provenance.json)
и проверяется перед обычным офлайн-импортом. Внутри снимков находятся hashes
распакованных исходных пакетов (`provider.SaveAsset`, не JSON-экспорт), locres,
оригинального mapping, Headers.zip, CustomVersions и utoc. Build и CL совпадают
с ранее закреплёнными Docs. Каталог вручную не редактируется.

## Как разрешён слот плавильни

В Docs у Smelter `mCanChangeProductionBoost=True`,
`mOverrideProductionShardSlotSize=False`, а неиспользуемое собственное поле
`mProductionShardSlotSize=0`. Asset
`/Game/FactoryGame/-Shared/Blueprint/BP_BuildableSubsystem` задаёт
`mDefaultProductionShardSlotSize=1`.

Комментарий поля в `Source/FactoryGame/Public/FGBuildableSubsystem.h`
подтверждает применение общего значения ко всем зданиям без override.
Соответствующий флаг описан в `Buildables/FGBuildableFactory.h`.
Импорт теперь разрешает эффективное значение по этим правилам. Проверочный
расчёт: одна плавильня, 30 руды/мин и один Somersloop → 60 слитков/мин, 16 МВт.

## Семантика графа MAM

Проверено тело Blueprint-функции `Widget_MAMTree_Grid.GetNodeState`:
начальное `IsAvailable=true` (@513), цикл Parents (@690), сброс перед каждым
родителем (@880), проверка завершения (@1097), установка true при успехе
(@1149) и прерывание цикла (@1160). Значит, родители соединены **ИЛИ**;
пустой список не добавляет требования. UnhiddenBy также использует ИЛИ.
Путь asset, функция и offsets сохранены в `semantics.evidence` снимка.

Условия родителей и видимости дополняют условия самой схемы из Docs и открытие
ветки. Подбор предметов, события и завершение исследований калькулятор не наблюдает.
Граф объясняет связи, а завершение пользователь отмечает самостоятельно.
Открытие рецепта не покупает его предков автоматически.

После восстановления отсутствующих нулевых X/Y в структурах **пять узлов**
Кварца/Серы всё равно содержат ссылки на отсутствующие координаты. Это свойство
исходных assets; сохранены и координаты, и неизвестные альтернативы. У каждого
есть действующий родитель ИЛИ. Неизвестная ссылка не считается выполненной.

## Границы порядка категорий

Названия и принадлежность взяты из `FGItemCategory`, `mCategory`,
`mOverriddenCategory` и RU/EN `AllStringTables.locres`. Семь категорий не
сериализуют приоритет; он сохранён как null. Их положение и порядок при равных
приоритетах дополняются русским алфавитом. Приоритеты рецептов берутся из Docs.
Полное совпадение расположения всех пунктов игрового меню не заявляется.

## Извлечение и проверка парсера

Использован CUE4Parse **1.2.2.202609**, commit
`b4e95441bcf0c975eb3adb68c0fb44c740c2cf62` (Apache-2.0), через PowerShell
7.6.5/.NET 10.0.11. Настройки: `GAME_UE5_6`, package versions 522/1017,
поставляемые игрой CustomVersions и FactoryGame.usmap. Прочитаны pak и utoc,
монтируется 48573 виртуальных файла. Для bytecode включён `ReadScriptData`.
Документация инструмента использована только для конфигурации:
[извлечение игровых файлов](https://docs.ficsit.app/satisfactory-modding/latest/Development/ExtractGameFiles.html).

Закреплённый usmap v1 содержит 44 OptionalProperty без внутреннего типа,
который ожидает этот CUE4Parse. Для исследования создана отдельная совместимая
копия: изменены только эти теги на Unknown. Оригинал сохранён. Затем проверено
транзитивное замыкание всех выбранных типов, родителей и встроенных структур,
включая array/set/map: 496 пакетов, 658 типов, 150 native mappings,
**ни одного пересечения с изменёнными OptionalProperty**. Результат и метод
находятся в `provenance.mappingVerification`. Это не универсальная поддержка
любых assets игры; при новом извлечении проверку необходимо повторить.

Для пересоздания нормализованных файлов достаточно закреплённых снимков:
`pnpm data:import`. Установленная игра и извлекатель при этом не нужны.
Для обновления первичных снимков требуется заново извлечь перечисленные классы
и локализацию из соответствующей сборки, проверить mapping, ссылки и семантику,
обновить hashes; изменение одного лишь номера версии проверкой не считается.
DLL инструмента, полные assets, локализации и исследовательские файлы остаются
в игнорируемом output; в приложение они не включаются.
