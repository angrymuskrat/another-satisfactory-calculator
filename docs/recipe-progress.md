# Быстрая настройка рецептов по прогрессу

Реализовано по согласованному предложению от 2026-09-07.
Вход: «Рецепты» → «Быстрая настройка по прогрессу».

## Сценарий

1. Выбрать фазы, уровни и отдельные этапы HUB. «Выбрать всё до уровня»
   заменяет текущий выбор HUB, сохраняя выбор MAM. Флажки групп имеют
   состояние частичного выбора. Стартовые рецепты — отдельная схема
   Schematic_StartingRecipes_C, включённая в уровень 0.
2. Независимо отметить исследования MAM по направлениям. Завершение фазы,
   подбор предметов и предки исследования автоматически не отмечаются.
3. Выбрать режим альтернатив и действие. «Заменить набор» выключает остальные
   рецепты и заменяет доступные здания/транспорт эффектами выбранных схем.
   «Добавить к текущему» сохраняет старые возможности и добавляет выбранные.
   Заказ, источники, частоты, энергетические лимиты и физические линии сохраняются.
4. Просмотреть добавляемые/выключаемые рецепты, здания, транспорт и связанные
   фабрики, затем применить. Отмена не меняет план. Изменение плана или мира
   делает просмотр устаревшим. Фокус переходит в просмотр и возвращается
   к вызвавшей его кнопке после отмены или применения.

Режимы альтернатив:

- Без альтернатив: при замене исключаются все рецепты с признаком alternate;
  при добавлении уже включённые сохраняются.
- Сохранить выбранные: сохраняет личный набор альтернатив и применяет выбранные
  исследования MAM, включая их альтернативные рецепты.
- Все подходящие из дисков: при замене формирует набор заново из выбранного
  прогресса и подходящих дисков; при добавлении сохраняет старые рецепты.

Отдельная кнопка «Добавить все подходящие альтернативы» добавляет только
рецепты из дисков. Она не включает обычные рецепты, не меняет оборудование
и не отмечает выбранные для предпросмотра этапы завершёнными.

## Данные и условия дисков

Импорт из закреплённых Docs той же сборки сохраняет Unlock.sourceType и
selectionDependenciesKnown. Последнее поле подтверждает только распознавание
сериализованных условий схемы и отсутствие ограничений события/public build.
Оно не заменяет prerequisitesKnown и не подтверждает прохождение игры.
Исходные SHA-256, сборка и дата остаются в provenance каталога/progression.

Источником диска служит EST_Alternate, а не Recipe.alternate или префикс имени.
Обход schematicIds включает дочерние выдачи: дистиллированный кремнезём
относится к дискам через родительскую схему. Турботопливо, угольный брикет
и синтетическая ткань относятся к MAM.

Проверяются AND между prerequisiteGroups и OR внутри группы. Выбранные схемы
раскрываются через schematicIds; их предпосылки не покупаются автоматически.
Неизвестные условия не дают автоматического разрешения. mTechTier альтернативы
не используется как самостоятельное условие доступности. Наличие ингредиентов
не означает выполнение исследования, а их отсутствие не запрещает выбор рецепта.

Массовое добавление дисков — явное допущение для расчёта по известным условиям,
а не гарантия появления конкретной награды или отметка уже изученного диска.
Выполнимость производства и доступность здания проверяются отдельно.
Сезонные рецепты вне расчётного каталога не добавляются.

## Фильтры и порядок

Независимы источник (HUB/диски/MAM/другие), направление MAM, состояние,
категория, поиск и «Скрыть закрытые». Старый фильтр всех альтернатив сохранён.
Фильтры не изменяют набор включённых рецептов.

По умолчанию порядок: ранние уровни HUB → этапы; затем независимые направления
MAM, другие/неизвестные условия. Внутри MAM используется глубина известных
родительских связей; это справочный порядок, а не доказательство обязательного
пути. При равных условиях используется русский алфавит и стабильный ID.
Дочерняя custom-схема наследует источник открытия. Для дисков уровень выводится
из требований: максимум обязательных групп, минимум альтернатив внутри группы.
Нельзя использовать уровень выходного предмета вместо уровня альтернативы.
Если существуют пути HUB и MAM, в общем порядке показывается подтверждённый
уровень HUB; MAM остаётся доступен через фильтр направления и все пути карточки.
Рецепты без сопоставленного источника находятся в отдельной последней группе.
Доступны также алфавитная сортировка и прежняя группировка по категориям.

## Сохранение и границы

Plan.recipeProgress.unlockIds — необязательное поле самостоятельного плана.
Оно проходит runtime-валидацию, сохраняется в черновике/JSON/профиле и переносится
при создании мира из плана. Старые документы не требуют миграции. Проверка
ссылок на текущий каталог выполняется при загрузке; API профилей, как прежде,
проверяет структуру документа независимо от версии каталога.

Для плана с миром выбор берётся из unlockedMilestoneIds мира. Общий мир меняется
через previewWorldUpdate/applyWorldUpdate и существующую атомарную запись workspace
с проверкой владельца и ревизии. Все связанные фабрики получают новый снимок.
Локальные запреты других фабрик сохраняются. В активной фабрике сохраняются только
изменяемые настройки рецептов, зданий, транспорта и прогресс; её несохранённый
заказ не записывается скрыто. Если общего мира нет в текущем пространстве,
интерфейс явно изменяет только снимок самостоятельного плана.

Выключение технологий может сделать сохранённые линии/источники недоступными;
они не удаляются и не перестраиваются автоматически. Рецепт может быть открыт,
но недоступен для расчёта из-за здания или других ограничений.
