# Языковые пакеты: дизайн

Дата: 2026-11-28. Статус: черновик на согласовании.

Пометки: **[Пользователь]** — сказано пользователем; **[Моё решение]** —
выбрано исполнителем, можно оспорить.

## Зачем

Калькулятором должны пользоваться и другие игроки, и сам автор с английским
клиентом игры. Интерфейс и названия из игры показываются на выбранном языке.
Сейчас языков два — русский и английский; третий добавляется новым пакетом
без правок по всему коду. **[Пользователь]**

## Цели

- Все тексты интерфейса, названия предметов, рецептов, зданий, добытчиков,
  транспорта, категорий, этапов и исследований — на выбранном языке.
- Язык переключается сразу, без пересчёта и без перезагрузки.
- Сохранённые планы, экспорт, ссылка на заказ и будущий кеш отчёта (этап 5
  редизайна) не зависят от языка.
- Новый язык = один файл пакета интерфейса, один файл названий из игры,
  одна строка в списке языков.
- Этап 4 редизайна («Язык и голос») правит уже вынесенный русский пакет.

## Не цели

- Перевод пользовательских данных: имён миров, фабрик, линий, отгрузок,
  профилей. Имя по умолчанию («Фабрика 1») создаётся на языке момента
  создания и дальше хранится как введённое пользователем.
- Перевод проектной документации, комментариев, сообщений коммитов.
- Языки с письмом справа налево и отдельная вёрстка под них.
- Перевод логов сервера.

## Анти-цели

- Смешанный экран: английский интерфейс с русскими фразами решателя.
- Приблизительный перевод названия из игры, выданный за игровой.
- Скрытая миграция сохранённых данных ради языка.
- Зависимость ядра расчёта от языка интерфейса.

## Что есть сейчас

- Русские строки в коде: около 840 строк в `apps/web/src` (46 файлов), 200
  в `packages/domain`, 190 в `packages/solver`, 26 в `apps/api`.
- Каталог: у `items`, `buildings`, `recipes`, `schematics`, генераторов есть
  `name` (русское) и `nameEn`. У `miners`, `belts`, `pipes`, `researchTrees`,
  `gamePhases` — только `name`. `categories` — массив русских строк, и эта же
  строка стоит в `recipe.category` как идентификатор.
- Импорт (`scripts/import-game-data.mjs`) читает `Docs-en-US.json.gz`
  и `Docs-ru.json.gz` из `packages/game-data/source/`; английские названия
  категорий есть в `menu-assets.json` (`nameEn`).
- Ядро само собирает фразы: `Result.message`, `Result.warnings`, подписи
  вариантов (`packages/solver/variants.ts`), ошибки независимого валидатора
  (`packages/solver/validate.ts`), ошибки проверки плана и файлов
  (`packages/domain/validation.ts`, `recipeSettingsFile.ts`, `worlds.ts`),
  подписи узлов схемы (`packages/domain/schematic.ts`), подписи источников
  (`sourceLabel.ts`). API отдаёт `{ error: 'русский текст' }`.
- Поиск: `normalize` в `controls.tsx` уже ищет по `name` и `nameEn`; остальные
  поиски (`recipeCatalog.ts`, `schematicSearch.ts`, `Worlds.tsx`,
  `AnalysisPanel.tsx`) — только по русскому тексту, регистр приводится
  с локалью `'ru'`.
- `index.html`: `lang="ru"`, русские `title` и `description`.
- Тесты: 71 файл с русским текстом; около 100 проверок в Vitest и около
  1200 строк в Playwright сверяют русские фразы.

## Подходы

1. **Коды вместо текста.** Ядро возвращает код и параметры, фразу собирает
   интерфейс. Язык переключается без пересчёта, сохранённое не зависит от
   языка. Самый большой объём правок в ядре и тестах.
2. **Язык передаётся в расчёт.** Меньше правок, но смена языка требует
   пересчёта, сохранённый отчёт остаётся на языке расчёта, ядро зависит
   от языка интерфейса.
3. **Ядро не трогать.** Быстро, но английская версия смешанная.

Выбран подход 1. **[Пользователь]**

## Решения

### Выбор языка

- При первом открытии язык берётся из `navigator.languages`: первый язык,
  для которого есть пакет; если такого нет — английский. **[Пользователь:
  «и то и другое»; порядок запасного языка — моё решение]**
- Выбор пользователя хранится в `localStorage` под ключом
  `planovy-otdel:locale:v1` и важнее языка браузера. **[Моё решение]**
- Для аккаунта выбор дополнительно хранится необязательным полем `locale`
  внутри JSON workspace (столбец `workspaces.data`); схема SQLite не меняется.
  Отсутствие поля читается как «не выбрано». Данные при загрузке не
  переписываются. **[Моё решение; требование «запоминать в профиле» —
  пользователя]**
- Поле записывается только при явном выборе языка вошедшим пользователем.
  При входе: если в этом браузере язык уже выбран явно, он остаётся; если
  нет, а в workspace поле есть — берётся оно. **[Моё решение]**
- Переключатель — в шапке, рядом с профилем: кнопка с кодом языка и меню
  со списком языков, названных на самих себе («Русский», «English»).
  Пока в списке один язык, переключатель не показывается. **[Моё решение]**
- При смене языка обновляются `document.documentElement.lang`, `title`
  и `meta[name=description]`.

### Пакет интерфейса

- Без библиотеки. `apps/web/src/i18n/`:
  - `locales.ts` — список языков: `id`, самоназвание, тег для `Intl`;
  - `ru.tsx` — исходный пакет, объект со вложенными разделами по экранам;
  - `en.ts` — объект типа `typeof ru`; отсутствие ключа — ошибка компиляции;
  - `index.tsx` — `LocaleProvider`, хуки `useT()` и `useLocale()`.
- Значение ключа — строка или функция от параметров, возвращающая строку
  или `ReactNode`. Множественные формы — через `Intl.PluralRules` с тегом
  языка; помощник `plural(tag, count, forms)` лежит в пакете.
- Числа: `format()` из `controls.tsx` берёт тег языка (русский — запятая,
  английский — точка). Единицы («шт/мин», «м³/мин», «МВт») — в пакете.
- Чистые функции вне React, которым нужен текст, получают `t` аргументом.
  **[Всё — моё решение]**

### Названия из игры

- `catalog.json` и его версия не меняются: поля `name` и `nameEn` остаются,
  сохранённые файлы с прежней версией каталога читаются как раньше.
- Импорт дополнительно пишет `packages/game-data/locales/<язык>.json`:
  словари `id → название` по видам `item`, `recipe`, `building`, `miner`,
  `belt`, `pipe`, `category`, `schematic`, `researchTree`, `gamePhase`,
  `generator`. Файл генерируется, вручную не правится.
- Источник — только данные той же сборки игры: `Docs-<язык>.json.gz`,
  `menu-assets.json`, таблицы строк. Если названия в данных игры нет,
  оно задаётся в `overrides.json` (`manualNames`) и перечисляется
  в `audit-report.json` (`verification.manualNames`). Схема без названия
  в данных игры на обоих языках записи не получает.
- Идентификатор категории остаётся прежней русской строкой: менять его —
  значит менять каталог и сохранённые настройки. Название категории берётся
  из словаря по этому идентификатору.
- Интерфейс получает название через одну функцию `gameName(kind, id)`.
  Запасной порядок: словарь выбранного языка → английский словарь → `name`
  из каталога.
- Язык получает файл названий, только если в `source/` лежит
  `Docs-<язык>.json.gz` той же сборки. В этой работе языков два. Механизм
  третьего проверяется тестом на вымышленном языке без файла названий:
  интерфейс показывает английские названия.
- `locales/ru.json` для категорий сопоставляет строку саму с собой; английские
  названия категорий импорт переносит из `menu-assets.json` в `locales/en.json`.
- Порядок рецептов и категорий остаётся импортным (приоритет меню игры).
  Там, где порядок сейчас алфавитный, сортировка идёт во время показа
  по названию на выбранном языке. **[Всё — моё решение]**

### Ядро: коды вместо текста

- `packages/domain/messages.ts`: тип `Message = { code: MessageCode;
  params?: Record<string, MessageParam> }`, где `MessageCode` — объединение
  строковых литералов.
- `MessageParam` — число, строка (только введённое пользователем: имя линии,
  фабрики), ссылка на название из игры `{ ref: 'item' | 'recipe' | 'building'
  | 'miner' | 'belt' | 'pipe' | 'category'; id: string }` или вложенный
  `Message`. Готовых названий из каталога в параметрах нет.
- Интерфейс разворачивает параметры одной функцией `renderMessage(message)`:
  ссылки — через `gameName`, вложенные сообщения — рекурсивно, затем вызывает
  функцию пакета.
- `Result.message` становится `Message`, `Result.warnings` — `Message[]`,
  то же для `pareto.failures[].message` и ошибок валидатора.
- `ProductionVariant.label` и `pareto.failures[].label` убираются: подпись
  выводится в интерфейсе из `id` варианта и режима плана.
- Ошибки, которые сейчас бросаются с русским текстом, становятся
  `DomainError` с полями `code` и `params`; `message` у него — сам код.
- Модели схемы и строительства хранят идентификаторы; составная подпись
  («Разделитель: Железная руда») становится `Message`.
- Тексты для кодов лежат в пакетах интерфейса в разделе `core`; тип
  раздела — `Record<MessageCode, …>`, поэтому код без текста не компилируется.
- API добавляет в ответ об ошибке поле `code` (и `params`, если есть).
  Поле `error` с русским текстом остаётся только для вкладок со старой
  версией интерфейса, открытых во время обновления стенда. Интерфейс
  показывает текст по `code`, а при незнакомом коде — `error`.
- Ошибки чтения файлов больше не приклеивают сообщение Zod: код ошибки
  получает параметр `path` (путь к полю), текст Zod пользователю не показывается.
- Типы меняются сразу, без переходного адаптера: PR A2 в одном изменении
  переводит ядро на `Message` и переключает всех потребителей в `apps/web`
  на `renderMessage` с разделом `core` русского пакета.
- Текст ядра нигде не сохраняется. В браузере хранятся черновик плана
  (`ficsit-plan-v1`), workspace (`ficsit-workspace-v1`) и отметки постройки
  диапазонами (`satisfactory:construction:v1`); в SQLite — документы и
  workspace. `Result`, подписи вариантов и `MissingSupply.label` живут только
  в памяти вкладки. Поэтому A2 не меняет форму сохранённых данных и правило
  чтения старого текста не нужно. Имена линий и отгрузок в плане — данные
  пользователя, они не переводятся. **[Всё — моё решение]**

### Поиск

- Поиск предметов, рецептов и узлов схемы ищет по названию на выбранном
  языке, по русскому и по английскому одновременно. **[Пользователь: поиск
  понимает оба языка]**
- Приведение регистра — с тегом выбранного языка; замена «ё → е» остаётся.

### Тесты

- Vitest: проверки фраз ядра переходят на коды и параметры. Список
  изменённых `expect` — в описании PR.
- Playwright: в конфигурации явно задаётся `locale: 'ru-RU'`, существующие
  сценарии остаются русскими.
- Новые проверки:
  - в английском пакете нет кириллицы;
  - у каждого идентификатора каталога есть название в каждом файле
    `locales/<язык>.json`;
  - язык из браузера, сохранённый выбор и переключение без пересчёта;
  - обход всех экранов с английским языком: на странице нет кириллицы,
    кроме введённого пользователем;
  - поиск находит предмет по русскому и по английскому названию на обоих
    языках;
  - сохранённый до изменения план открывается без изменений.

### Правила проекта
