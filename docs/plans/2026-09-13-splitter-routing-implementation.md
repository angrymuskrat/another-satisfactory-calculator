# План реализации распределения конвейеров

Для исполнителей: использовать subagent-driven-development с отдельными
владельцами файлов и проверкой результата каждого этапа.

Цель: отключаемое ограничение распределения реальными разделителями и
соединителями, проверенная топология результата и справочник до глубины 4.

Спецификация: [согласованный проект](2026-09-13-splitter-routing-design.md).
Стек: TypeScript, React, HiGHS, Vitest, Playwright; новых зависимостей нет.
Рабочая ветка: `codex/splitter-routing`.

Состояние на 2026-09-13: этапы 1–4 реализованы, общий Vitest/TypeScript/build
прошли, финальный UI-прогон завершается. Глобальная оптимальность производственного поиска и практическое
завершение полного D4 не подтверждены. Текущее состояние: [STATUS](../STATUS.md).

## Общие ограничения

- Глубина — максимум устройств на пути, включая разделители и соединители.
- Учёт выключен по умолчанию; отсутствие настройки не меняет старый расчёт.
- При включении учитываются полные векторы потоков и пропускная способность.
- Производственные циклы сохраняются, обратные ленты внутри блока не разрешены.
- Жидкости не получают модель равных долей конвейерного разделителя.
- Ограниченные вычислительные ресурсы не являются доказательством невыполнимости.
- Баланс, жёсткие границы и выбранная политика выпуска не ослабляются.
- Пользовательские данные, Docker и зависимости не изменять.

## 2. Рациональная модель и справочник

Выполнено отдельной подзадачей математической модели; файлы нового модуля
`packages/domain/beltRouting.ts` и `tests/belt-routing.test.ts`.

Математическая модель: состояние — мультимножество свободных выходов с точной
долей, глубиной и ссылкой на происхождение. Операция потребляет один выход
и производит 2/3 равных либо потребляет 2/3 выхода и создаёт их сумму. Новая
глубина равна максимуму глубин входов + 1. Операции допустимы до заданного D.
Доли можно представить целыми весами относительно `6 ** D`.

- [x] Ручные тесты: D1 содержит (1/2,1/2), (1/3,1/3,1/3); D2 содержит
  (1/3,2/3) с реальным соединителем; схема 1/5 не допускается без возврата.
- [x] Реализовать независимый валидатор операций и восстановление свидетеля.
- [x] Удалять дубликаты по мультимножеству долей/глубин; для справочника одинаковые
  конечные векторы показывать один раз, сохраняя один проверенный свидетель.
- [x] Перебор прерываемый: состояние поиска сохраняется между порциями, признак
  complete устанавливается только после исчерпания всей очереди.
- [x] Замерить число состояний и время для D1–4; не объявлять ограниченный
  или не законченный перебор полным. Математическая проверка определяет,
  достаточно ли этой модели для принятой полноты.

Математика и измерения: [заметки](2026-09-13-routing-math-notes.md).
D1/D2/D3 исчерпаны: 3/19/1355 векторов, включая прямую ленту. Перебор D4
точный и возобновляемый, но полный прогон не завершён. Контроль за 45 с дал
около 972 242 векторов / 3 265 508 состояний при RSS около 846 MB;
это промежуточные числа, не полный размер и не предел памяти.

Файлы: новый модуль в `packages/solver`, `build.ts`, `solve.ts`, `validate.ts`,

  Каждый участок имеет upper=выбранная пропускная способность.

  доказательстве полной модели.
- [ ] Проверить альтернативы, частоты, два режима, три политики, партии,
  бюджет дополнительных машин, несколько источников и производственные циклы.

Реализованы `beltRouting.ts`, `beltNetwork.ts`, `beltTemplate.ts` решателя,
контракты физических концов и независимые валидаторы в domain. Состав машин
выбирается ограниченным поиском; быстрый шаблон предлагает только топологию,
её точные уравнения включаются до целей. Неудача не меняет модель, общая
MIP-топология остаётся отдельным кандидатом. Найденный результат approximate;
глобальные максимум выпуска и минимум машин с логистикой не доказаны.
Потеря выпуска внутри поиска имеет общий исходный выпуск; бюджет физических
машин общий между проверяемыми составами. Логистические устройства в этот
бюджет не входят. Внешняя поставка — независимые равные входные ленты;
разделение до границы фабрики не рассчитано. Для каждого предмета выделяется
отдельный Sink. Жидкости и производственные циклы сохраняют прежнюю семантику.
