# План развития для среднего этапа игры

Статус: **предложение, не согласовано к реализации**. Составлено 2026-10-03 по
результатам продуктового ревью: стенд осмотрен гостем, выполнены два расчёта
(усиленные пластины из одного узла; 10 тяжёлых модульных каркасов/мин при
неограниченном сырье), сверены аудиты, STATUS и инвентаризация кода. Тесты при
ревью не запускались. Целевой игрок — средний этап (нефть, алюминий, Tier 5–6).

Каждый пункт перед реализацией получает отдельную спецификацию с контрактом,
владельцами файлов и проверками по AGENTS.md.

## Наблюдения ревью

- Ядро, инструкция строительства, ведомость материалов, варианты и схемы работают.
- Метрики, важные на среднем этапе, почти не влияют на результат: веса сырья по
  умолчанию равны 1 и в smooth-power применяются последними (машины → энергия →
  сырьё); число разных рецептов и логистика на границе фабрики не показываются.
- Интерфейс перегружен повторяющимися оговорками модели и справкой о данных.
- Выбор полезной альтернативы требует ручной отметки до 12 из 111 проверок.
- Даже тривиальный план считается ~10–12 с: последовательно решаются два варианта.

## Этап 1. Упрощение (S)

- [x] Оговорки модели свёрнуты в блок «О модели» (результат и карточки
  вариантов). Статус решателя и ситуативные предупреждения (неизвестная энергия
  импорта, оценочная мощность, отгрузки, усилители) остаются на виду. Решатель
  отдаёт постоянные границы модели в Result.modelNotes, ситуативные — в warnings.
  Справка о каталоге уже была свёрнута (`<details>`), изменений не потребовалось.
- [x] Ведомость материалов — одна таблица «Материал / Новые / Всего».
- [x] Природные ресурсы без заданного источника и с нулевым расходом скрыты
  в карточках вариантов и в «Загрузке источников»; заданные источники с нулевым
  расходом остаются. Ненулевые малые потоки не скрываются.

Критерий: на экране результата нет повторов одной оговорки; честность статусов
и границ модели сохранена (требования AGENTS.md не ослабляются).

## Этап 2. Редкое сырьё и выбор альтернатив (M)

### 2.1 Веса сырья по редкости

- [ ] Импортировать суммарный выход узлов карты по ресурсам (чистота × базовая
  скорость) с фиксацией источника, версии игры, даты и статуса проверки.
- [ ] Пресет весов «по редкости»: вес обратно пропорционален запасу карты;
  ручные веса остаются. Пресет явно обозначен как условная стоимость.
- [ ] Показывать расход каждого ресурса как долю лимита мира/карты.
- [ ] Третья карточка варианта «Экономия редкого сырья»: после выпуска
  минимизируется взвешенное сырьё, затем машины и энергия.

Критерий: на контрольном примере с бокситом/катерием вариант меняет рецепт по
сравнению с компактным; МВт и предметы не суммируются в одну цель.

### 2.2 Рейтинг альтернатив «что даст мне этот диск»

- [ ] Кандидаты — открытые, но выключенные альтернативы, которые производят или
  потребляют предметы текущей рассчитанной цепочки (ожидается 10–25).
- [ ] Для каждого — повторное решение копии плана с общим бюджетом времени;
  таблица изменений: выпуск, машины, средняя МВт, взвешенное сырьё, новые ресурсы.
- [ ] Заменяет ручной список 111 проверок как основной сценарий; ручной выбор
  остаётся для совместных проверок.

Критерий: устаревшие ответы worker не показываются; тайм-аут отдельных
кандидатов отображается явно и не выдаётся за «нет пользы». Рейтинг использует
веса из 2.1, чтобы не советовать рецепт, расходующий редкое сырьё.

## Этап 3. Простота и логистика (S–M)

- [ ] KPI «разных рецептов» и «промежуточных предметов» в результате.
- [ ] Вариант «Проще построить»: после выпуска минимизировать число разных
  рецептов (есть в цели buildings как вторичный критерий), затем машины и энергию.
- [ ] Граница фабрики: для каждого входа и выхода — число лент/труб выбранного
  уровня (сейчас показывается только для готовой продукции).

## Этап 4. Энергия и отзывчивость (S–M)

- [ ] Справка «чем покрыть»: число угольных/топливных генераторов и расход топлива
  для средней и пиковой мощности. Генерация в оптимизацию не входит.
- [ ] Показывать основной вариант сразу после решения, экономичный — по готовности.
