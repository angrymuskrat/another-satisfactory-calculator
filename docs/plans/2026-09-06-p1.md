# Реализация P1 игрового аудита

Основание: запрос пользователя реализовать P1 из `docs/audits/2026-09-06-gameplay-audit.md`.
Объём: F01–F07 и F11; P2 не включён.

## Решения

- Сохраняется модель заданных частот. Строительная инструкция показывает физические
  машины, рабочую частоту, средние потоки и долю работы с простоями. Автоматическая
  замена частот и динамическая симуляция сети не выполняются.
- Для максимальной нагрузки, лимитов типов зданий и цели «меньше зданий» решатель
  получает целочисленные переменные количества машин. Пиковая нагрузка включает
  задействованных добытчиков и утилизаторы; резерв вычитается из лимита сети.
- При равных основных целях выбирается меньше разных рецептов. Для дискретного
  выбора основные стоимости считаются равными в пределах численного допуска
  `1e-7 + |цель| * 1e-8`; пользовательские ограничения остаются жёсткими.
- Минимумы и максимумы продуктов — жёсткие ограничения, действующие также при
  разрешённой потере выпуска. Недостижимый минимум не снимается молча.
- Мир хранит открытия; фабрика хранит полный план и снимок прогресса мира. Обновление
  снимка требует просмотра изменений. Старые планы сохраняются без изменения смыслов.
- Альтернативы и расширения проверяются повторным решением всей цепочки. Исходный
  план остаётся прежним; результаты устаревают при его изменении.
- Категории остаются явно тематическими до появления подтверждающих assets.
  Стоимости зданий и открытия импортируются только при наличии исходных данных.

## Порядок и владение файлами

1. Основной агент: контракты/валидация, build/solve/validator, Planner, стили,
   интеграционные проверки и STATUS.
2. Агент миров: worlds, Worlds, App, Profiles, API, хранение и тесты изоляции.
3. Агент каталога: Recipes, analysis, AnalysisPanel, worker и тесты сравнений.
4. Агент строительства: Results, Technologies, construction/dependencies, тесты.
5. Агент данных: воспроизводимый импорт и каталог, coverage и catalog tests.

## Проверяемые результаты

- Ручные примеры: минимум младшего продукта при приоритете/весах, верхний предел,
  невыполнимые минимумы, средняя мощность ниже допустимой при превышенном пике,
  резерв, лимиты типов зданий, различие целей энергии и количества машин.
- Независимый validator обнаруживает подмену потоков, MW и физических количеств.
- Сравнение альтернатив/расширений сохраняет исходный план и подтверждает пользу.
- Миры: миграция, наследование, предварительный просмотр, сохранение/загрузка,
  ревизии, изоляция пользователей.
- Строительство: нелинейная мощность при заданной частоте, материальная ведомость,
  порядок зависимостей и единый блок цикла.
- После интеграции: Vitest, TypeScript, production build, Playwright desktop/mobile.
  Непроверенные свойства отмечаются в STATUS без утверждений о полном покрытии.
