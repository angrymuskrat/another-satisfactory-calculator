## Полнота справочника

Для одного входа единичного расхода, положительных конечных выходов,
ациклических split(2/3) и merge(2/3), максимальной глубины D модель конечна:

- На глубине j максимум 3^(j−1) устройств. У каждого узла есть путь от входа,
  а путей такой длины не больше указанного числа.
- Всего устройств не больше (3^D−1)/2: при D=4 это 40; выходов не больше 3^D=81.
- На любом пути знаменатель доли имеет вид 2^a·3^b, a+b≤D. Суммы путей
  сохраняют делимость знаменателя числом 6^D. Поэтому точная решётка
  с общим знаменателем 6^D полна: при D=4 это 1296, а не произвольное округление.

Состояние перебора — мультимножество живых лент `(числитель, глубина)`.
Начальное состояние `(6^D, 0)`. Разделитель забирает одну ленту и создаёт
две/три равные, соединитель забирает две/три разные ленты и создаёт сумму.
Новая глубина равна максимуму глубин забранных лент плюс один.
Все оставшиеся ленты являются совместно существующими конечными выходами.

Каждая ациклическая сеть допускает топологический порядок устройств;
применение этого порядка воспроизводит её в переборе. Каждое действие перебора
строит допустимое устройство и потребляет реальные ленты единожды. Эти два
направления доказывают полноту и корректность. Состояния с одинаковым
мультимножеством долей и глубин имеют одинаковые продолжения: происхождение
неиспользованных лент не влияет на дальнейшие действия. Склеивание таких
состояний безопасно при сохранении одного воспроизводимого свидетеля.

Перебор отдельных скалярных долей недостаточен. Независимый выбор нескольких
достижимых дробей не доказывает их одновременную достижимость. Также нельзя
склеивать состояния только по долям, забывая глубины оставшихся лент.

## Реализованный контракт

`DistributionSearch(D).advance({maxStates, maxResults, deadline})` сохраняет
позицию внутри переходов текущего состояния и выдаёт только новые распределения.
`deadline` — абсолютный `Date.now()`, не `performance.now()`. `maxStates`
ограничивает число вновь начатых состояний за вызов; сохранённое текущее состояние
может быть дополнительно закончено. Нулевой бюджет ничего не делает.
`visited` — число обнаруженных состояний. `complete` становится истинным
только после полного исчерпания очереди. Неявного отсечения глубины, числа
выходов, устройств, состояний или результатов нет.

Распределение содержит полный упорядоченный вектор сокращённых дробей,
стабильный ID из этого вектора, фактическую глубину, число устройств и граф.
Прямая лента `[1]` включена с глубиной 0. Обход в ширину выбирает свидетеля
с минимальным числом устройств; минимальная глубина среди свидетелей с тем же
вектором отдельно не оптимизируется и не обещается. Параллельные рёбра графа
представляют разные физические порты, в частности два выхода одного split,
входящие в один merge; их нельзя склеивать для подсчёта портов.

`validateDistribution` независимо проверяет граф точными BigInt-дробями:
порты, равенство выходов разделителей, баланс соединителей, единственный вход,
сумму и полный вектор выходов, отсутствие циклов, восстановленную глубину,
счётчики устройств и метаданные. Проверка пропускной способности при пробном
расходе требует дополнительно сравнить расход каждой ленты с её пределом.

## Связь с производственным MIP

Справочник одного входа не заменяет совместную модель нескольких поставщиков.
Точный вариант при конечном числе физических выходных портов S:

1. Для каждого предмета задаются реальные выходные и входные порты каждой
   машины/добытчика/внешнего потока/утилизатора. Расход каждого порта связан
   с производственной переменной, а не вычисляется из результата после решения.
2. Между ними вводятся уровни устройств 1…D с рёбрами только вперёд. Полная
   верхняя граница устройств на уровне j равна S·3^(j−1), всего не более 40S
   при D=4. Соединитель получает до трёх входов; каждый порт соединён ровно
   одной физической лентой, ветвление без устройства запрещено.
3. Бинарные переменные задают активные порты, рёбра и тип устройства.
   Для выбранной топологии расход линейный: split равноделит общий вход,
   merge суммирует входы. Каждое ребро имеет `0≤f≤C·active`, где C —
   фактическая вместимость ленты; тот же C даёт корректный конечный big-M
   для условных равенств. Не следует брать произвольный огромный M.
4. Производственные циклы допустимы: глубина считается только между выходом
   машины и входом следующей машины. Нельзя обнулять глубину на произвольно
   вставленном промежуточном «блоке», иначе ограничение теряет смысл.
5. Все прежние цели выполняются последовательно внутри модели с топологией.
   Не следует сначала фиксировать свободный максимум или свободный минимум
   машин: они могут исключить весь допустимый вариант с разводкой.

Лобовая полная модель имеет порядка квадратного числа потенциальных связей
от числа устройств, то есть уже при сотнях физических портов непрактична.
Ленивое добавление кандидатов допустимо, но незавершённый поиск не доказывает
невыполнимость полной модели.

Для сохранения равномерной загрузки группы на конечном множестве слотов:
общая нагрузка одной машины z, бинарная активность a_i, нагрузка слота y_i.
При корректной максимальной нагрузке U вводятся `0≤y_i≤U·a_i`, `y_i≤z`,
`y_i≥z−U·(1−a_i)`, `0≤z≤U`; общий выпуск группы пропорционален сумме y_i.
Так исключается произведение количества машин на непрерывную загрузку.
Имеющиеся закреплённые/свободные линии сохраняют свои отдельные конфигурации.

## Границы и статусы производственного поиска

Если нет конечного лимита количества машин, число физических портов заранее
не ограничено. Один найденный производственный incumbent не даёт полной верхней
границы. Увеличение числа слотов с повторным совместным решением может найти
допустимый проверенный результат; его статус — приближение, пока глобальный
поиск не завершён. Невыполнимость ограниченного числа слотов означает только
неуспех этого подпространства. По сроку следует возвращать timeout/unknown,
а не infeasible. Сравнение двух найденных вариантов не доказывает оптимальность.

Доказанную конечную границу можно получить из ограничения пиковой мощности:
если каждый физический экземпляр типа имеет строго положительный минимум
пика p_min, число таких экземпляров не больше floor(P_available/p_min).
При этом надо отдельно учесть уже установленное оборудование, Sink, скважины
и неэнергетические внешние порты. Из одного лимита средней мощности такая
граница обычно не следует: сколь угодно много машин могут работать с малой
долей времени. Бюджет дополнительных машин опирается на минимум машин уже
в модели с разводкой, а не на минимум свободной LP.

Внешний `Source.kind=flow` требует явного определения физических входных лент.
Если произвольный внешний расход разрешить свободно назначать любому числу
независимых портов, можно скрыто реализовать произвольное деление до границы
модели. Нельзя назвать это доказанной физической разводкой единственного
источника. Если источник больше пропускной способности одной ленты, несколько
входных лент должны быть явно определены принятой моделью поставки.

Это технические границы доказательств. Они не дают разрешения заменять
согласованный совместный расчёт проверкой и округлением готового результата.

## Независимый обзор послойной производственной модели

Прочитаны `packages/solver/beltNetwork.ts` и `packages/domain/beltNetwork.ts`
после их появления в основной задаче. Для фиксированных физических концов
дополнительно верна двусторонняя граница числа слотов уровня j:
`min(S·3^(j−1), T·3^(D−j))`, где T — число физических входов потребителей.
Прямые ленты дополняют короткие пути до D слоёв и не считаются устройствами.
Обратная граница следует из максимального входящего ветвления 3 и одного
подключения конечного порта; прямая — из максимального исходящего ветвления 3.
Таким образом, это полная область топологий для заданных концов, а не
произвольный набор шаблонов. Уравнения равных выходов, количества портов,
индивидуальных ограничений ленты и параллельных соединений проверены чтением.

Дополнительно все 19 векторов справочника уровня 2 переданы в послойную
модель как один вход 36 и физические выходы с точными расходами. Все 19
решений получили Optimal, декодированные графы прошли независимую проверку;
прогон занял 1,45 с. Полнота перечисления конфигураций машин этим не доказана.
