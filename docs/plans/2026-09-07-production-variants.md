# Подбор вариантов производства

Согласовано пользователем: реализовать рекомендацию из обсуждения — две карточки,
максимальный выпуск и экономия энергии, затем выбор конкретного проверенного плана.

## Контракт

- Общий smooth-power и подбор частот сохраняются. Максимальный вариант использует
  нулевую потерю выпуска и компактную фабрику. Экономичный допускает выбранную
  потерю выпуска (по умолчанию 10%, 0–99%) только в режиме maximize без партии.
- После фиксации выпуска экономичный вариант находит минимум физических машин,
  ограничивает их число этим минимумом плюс явно разрешённые дополнительные
  машины (по умолчанию 0, целое 0–1000), затем минимизирует энергию и сырьё.
  Это конечный бюджет, не безусловный нелинейный оптимум энергии.
- Заданный заказ и партия не уменьшаются. Сохраняются все три политики,
  жёсткие минимумы/максимумы, ограничения мира, мощности, ресурсов и линий.
- Настройки сравнения сохраняются в settings.variantOptions:
  { outputLoss: number, extraMachines: number }. Выбранный экономичный расчёт
  сохраняет settings.smoothPowerExtraMachines; отсутствие поля сохраняет прежнюю
  последовательность целей. outputSlack хранит фактически выбранную потерю.
- packages/solver/variants.ts экспортирует solveVariants(catalog, plan, highs,
  deadline?), возвращает ProductionVariants { variants: ProductionVariant[],
  equivalent: boolean }, где ProductionVariant { id: 'maximum'|'economy',
  label: string, plan: Plan, result: Result }. Эквивалентные проверенные варианты
  объединяются в интерфейсе. Ошибки и тайм-ауты сохраняются отдельно.
- Общий бюджет worker 25 секунд, внешний таймер 30 секунд. Каждый вариант
  содержит исходный снимок своего плана. Выбор не вызывает повторного решения;
  выбранные plan/result переходят в подробности атомарно. Изменение входа делает
  карточки и подробности устаревшими; устаревший ответ нельзя принять.
- При выборе сохраняется конфигурация плана, а схема строится из соответствующего
  проверенного результата. Пользователь может вернуться к другим карточкам.
