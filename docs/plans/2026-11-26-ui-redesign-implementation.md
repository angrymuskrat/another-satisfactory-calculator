# Редизайн «Плановый отдел»: план реализации

> **Для исполнителей-агентов:** обязательный навык — superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans; шаги отмечаются чекбоксами `- [ ]`.

**Цель:** превратить интерфейс в «пульт инженера» с табло результата, читаемым со второго монитора, не меняя расчёт и сохранённые данные.

**Архитектура:** шесть этапов, каждый — отдельный PR в `master`, после каждого приложение работает. Этап 1 делает CSS читаемым без изменения отрисовки; этап 2 вводит мир и токены; этап 3 — табло и «Дальше строим» поверх существующих отметок постройки; этапы 4–6 — язык, состояния и доводка.

**Стек:** React 19 + Vite, CSS без препроцессора, Vitest, Playwright 1.63 (Chrome), HiGHS в Web Worker.

**Спецификация:** [2026-11-26-ui-redesign-design.md](2026-11-26-ui-redesign-design.md), макет — [mockups/2026-11-26-result-board.html](mockups/2026-11-26-result-board.html), контекст продукта — [PRODUCT.md](../../PRODUCT.md).

## Глобальные ограничения

- Правила `AGENTS.md` и `docs/invariants.md` важнее этого плана; расчёт (`packages/solver`) и контракты `packages/domain/types.ts` не меняются, кроме явно названных добавлений.
- Новое сохраняемое поле необязательно; отсутствие читается как прежнее поведение; скрытая миграция запрещена.
- Ключи `satisfactory:construction:v1`, `satisfactory:schematic-layout:v2:`, `ficsit-workspace-v1` не переименовываются и не переписываются.
- Название продукта — «Плановый отдел»; «FICSIT» не используется как бренд; логотип, шрифты, реплики и UI-ассеты игры не копируются.
- Шрифты — только OFL, self-host, запись в `THIRD_PARTY_NOTICES.md`.
- Sankey не добавлять; результаты — таблицы, карточки, раскрываемые разделы.
- Статус «Оптимум доказан» — только при `result.status === 'optimal'`.
- Движение: у каждой анимации есть замена при `prefers-reduced-motion`, сохраняющая смену состояния.
- Коммиты, push и PR — только по прямому указанию пользователя (личные правила); шаги «зафиксировать» ниже означают «готово к коммиту».
- Перед «готово» каждого этапа: `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm test:ui`, чеклист `local/pre-pr-checklist.md`; число находок детектора `impeccable detect --json <url> --viewport 1920x1080` и `390x844` на запущенной сборке не растёт. Скан исходников (`detect --json src`) после этапа 1 только справочный: его регулярки читают правило в одну строку и не видят многострочные правила развёрнутого CSS.
- Удаление теста или ослабление `expect` описывается в PR с причиной.

## Фокус ревью

1. **Изменённый план при показанном результате.** После правки плана табло (в том числе восстановленное из кеша) показывает «Требуется пересчёт» и приглушается; числа прошлой версии не выдаются за текущие. Тест — задача 5.2.
2. **Отметка с табло и из инструкции/схемы.** Отметка кнопкой табло видна в инструкции и схеме сразу, и наоборот; история отметок по-прежнему ограничена 20 записями. Тест — задача 3.4.
3. **Показ варианта без принятия, затем правка плана.** Переключение варианта не меняет план и не делает результат «устаревшим»; правка плана после показа даёт «Требуется пересчёт»; «Принять вариант» после правки недоступно. Тест — задача 3.2.
4. **Большая фабрика.** На контрольном заказе из 14 продуктов (`tests/largeOrderFixture.ts`, 200+ машин) «Построено» не превращается в стену ячеек: при M > 120 вместо ячеек — сегментная полоса. Тест — задача 3.3.
5. **Нет места в localStorage или приватный режим.** Ошибка записи кеша отчёта не ломает автосохранение черновика и отметки, экран говорит, что после перезагрузки придётся пересчитать. Тест — задача 5.1.
