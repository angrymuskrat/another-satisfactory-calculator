# Автоподбор частот для ровной нагрузки

Пользователь уточнил запрос 2026-09-07: активную долю времени нужно приближать
к 100% настройкой выработки машин. Согласован приоритет **минимум машин, затем
энергия**. Это заменяет первоначальный вариант с фиксированными частотами.

В «Целях и ограничениях» настраивается подбор двух вариантов: максимальный
выпуск и экономия энергии. Оба используют `Settings.objective = smooth-power`.
Профили, фабрики и JSON сохраняют настройки сравнения и выбранного варианта.
Частота технологий — верхний предел подбора; карточки рецептов используют её
только для справочного предпросмотра.

## Выбор варианта

После «Рассчитать» показываются карточки с выпуском каждого продукта, средней
и пиковой мощностью, числом производств и расходом источников. Экономичный
вариант показывает изменения относительно максимального и общий бюджет машин.
«Использовать вариант» открывает подробности и схему из того же проверенного
Plan/Result, без повторного запуска решателя. Можно вернуться к карточкам.
При изменении плана необходим новый расчёт. Ошибки и тайм-ауты каждого варианта
сохраняются отдельно; одинаковые допустимые конфигурации объединяются.

`settings.variantOptions.outputLoss` — допустимая потеря только для экономии,
0–99%, по умолчанию 10%. Максимальный вариант всегда использует outputSlack=0.
При пропорциях сохраняется доля общего выпуска; при приоритетах — доля каждой
последовательной цели; при весах — доля взвешенной суммы, не каждого продукта.
Жёсткие минимумы/максимумы не ослабляются. Target и исходная партия сохраняются.

`settings.variantOptions.extraMachines` — разрешённые дополнительные физические
машины, целое 0–1000, по умолчанию 0. Экономичный снимок сохраняет это значение
в `smoothPowerExtraMachines`. После фиксации целей выпуска решатель находит
минимум машин, задаёт конечный cap = минимум + добавление, затем минимизирует
энергию, сырьё и машины. Максимум выпуска не пересчитывается после установки cap,
поэтому допустимая потеря не применяется повторно к уменьшенному максимуму.
Бюджет включает добычу, компенсаторы, всех спутников используемой скважины и Sink.
`Result.machineBudget` показывает minimum/limit/used. Валидатор пересчитывает used;
оптимальность minimum подтверждается решателем, не повторным независимым решением.

Расчёты выполняются с общим сроком 25 секунд; первый получает до 45% остатка,
неиспользованное время доступно второму. Внешний worker-таймер — 30 секунд.
Это два допустимых варианта при конкретных бюджетах, а не вся граница компромиссов
и не доказательство глобального нелинейного минимума энергии.

По уточнению пользователя старые планы с другими целями удаляются при загрузке
вместо поддержки совместимости. Миры и планы smooth-power сохраняются;
повторный импорт прежних целей отклоняется явно, без скрытой замены.
Контракты ядра для фиксированных частот и их тесты остаются доступными отдельно.
[Задача интерфейса и правила очистки](plans/2026-09-07-planner-ui-cleanup.md).

## Компактный вариант и частоты

1. Выпуск по режиму и политике с прежними жёсткими границами и разрешённой
   потерей выпуска.
2. Целое число физических машин, включая добычу, скважины и Sink.
3. Средняя энергия с автоподбором частот производств.
4. Условная стоимость сырья и прежнее упрощение набора рецептов.

Для каждой конфигурации с одинаковым рецептом и усилением выбираются целое
число машин N и суммарное число циклов x в минуту. Если r — циклы одной машины
при 100%, каждая машина получает частоту c = x/(N·r). Частота ограничена снизу
1%, сверху — настройкой производства или исходной настройкой существующей
линии. При выпуске ниже нижнего предела частота равна 1%, остаётся доля простоя.
Частота в результате хранится в StepResult.clock и проверяется независимо.

Равномерное распределение выгоднее схемы «полные машины плюс одна на остаток»:
при выпуклой зависимости мощности от частоты одинаковые машины требуют меньше
энергии на одинаковой частоте. Например, заказ 7,5 усиленных железных пластин/мин
даёт два сборщика по 3,75/мин: **75% частоты, 100% активной доли времени**.
Общий заказ не меняется. Разные рецепты/усилители/существующие линии остаются
раздельными конфигурациями, частоты между ними могут различаться.

Закреплённые линии сохраняют количество, частоту, усилители и долю работы.
Незакреплённые линии сохраняют оборудование, допускают снижение частоты.
«Перестроить» разрешает заменить линии; «оставить» использует только существующие.
Добыча и скважины сохраняют настройки источников; их частоты не подбираются.

## Модель энергии и проверка

Для работающего производства P = P100·N·c^log2(2.5), с прежним множителем
усиления. Минимизация этой выпуклой функции при фиксированном N распределяет
нагрузку равномерно. Лимиты портов применяются к потоку каждой машины.

В HiGHS передаётся консервативная кусочно-линейная оценка функции:
эпиграф секущих с геометрическими узлами частоты (соседний узел не дальше ×1,25),
дополненный частотами 25%, 50%, 75%, 100% и далее через 25% до заданного предела.
Для каждой секущей P/P100 ≥ slope·x/r + intercept·N. Частота остаётся непрерывной,
узлы задают только приближение мощности. Ниже 1% средняя мощность линейна
по доле времени работы на 1%; пик не падает ниже мощности N машин на 1%.
Коэффициент пика берётся из соответствующего поля рецепта/здания.

Энергия учитывается до выбора рецептов, числа машин и потоков, включая
ограничения средней/пиковой мощности и резерв. Постобработка не заменяет
выбранную оптимизатором модель. Связь активности рецепта с бюджетом мощности
использует нижнюю стоимость цикла на 1%, чтобы не отсечь допустимые схемы.

После решения частоты и точные нелинейные мощности восстанавливаются из
потоков и количества оборудования. Независимый validator проверяет их по
каталогу, материальный баланс, предел частоты, ресурсы, усилители, здания и
исходные энергетические лимиты. Строительная инструкция повторно пересчитывает
показанные потоки и MW. Незагруженная мощность — сумма N·Pactive·(1−duty)
только производств; это не потребление standby и не разница пика и средней
мощности всей фабрики.

## Границы утверждений

Статус **approximate / «Допустимое приближение»** отделён от оптимума модели
фиксированных частот. Решение оптимально для консервативной линейной модели,
но глобальный оптимум исходной нелинейной задачи не доказан. Консервативная
оценка около жёсткого энергетического лимита может отсечь реально допустимую
схему или изменить минимальное число машин. Невыполнимость приближения
возвращается как ошибка с пояснением, без утверждения о невыполнимости точной
модели. Тайм-аут и численный сбой не подменяются успешным приближением.

Неограниченное добавление медленных машин ради экономии предотвращается
согласованным приоритетом их количества перед энергией. Точные заданные потоки
сохраняются. 100% активности недостижимы ниже минимальной частоты и могут быть
запрещены закреплёнными линиями. Фазы рецептурных циклов, синхронизация машин,
накопители, пуск и фактический временной график сети не моделируются.
