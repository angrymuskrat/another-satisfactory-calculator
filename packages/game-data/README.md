# Каталог установленной игры

Каталог рассчитан на **Steam build 24656030**. Строка публичной версии игры не
устанавливалась; каталог не объявляет себя актуальным для любой новой сборки.

Офлайн-регенерация из сохранённых источников:

```powershell
node scripts/import-game-data.mjs
node node_modules/vitest/vitest.mjs run tests/catalog.test.ts --configLoader runner
```

Восстановление игровых иконок из закреплённого upstream требует сети:

```powershell
node scripts/import-game-data.mjs --download-icons
```

Нормализованный файл нельзя править вручную. Исходные данные лежат в `source/`,
ручные сопоставления стабильных ID и тематических групп — в `overrides.json`.
Импорт проверяет SHA256 исходных файлов; загрузка иконок — Git blob SHA.
При обновлении игры сначала сохранить новые исходники и происхождение, затем
просмотреть diff, назначить ID добавленным предметам/рецептам и повторить проверки.

## Проверка и ограничения

- Импортируются 276 производственных рецептов, включая 110 альтернативных;
  152 предмета, 11 производственных зданий, утилизатор, пять добытчиков.
- 872 FGRecipe из дампа полностью распределены на импортированные и исключённые
  с причиной. Строительство, ручные/неподдержанные здания и сезонные рецепты
  доступны для аудита в `audit-report.json`, но не входят в модель фабрики.
- Количества жидкостей и газов делятся на 1000: литры дампа → м³. В каталоге
  сохраняются количества за цикл и длительность, а не округлённые потоки.
- 270 производственных рецептов upstream сопоставлены; два виртуальных
  реакторных цикла исключены. В игре добавлены шесть рецептов; три рецепта
  отличаются количествами/временем от upstream. Все расхождения записаны.
- Средняя мощность ускорителя подтверждена описанием продукта в самом дампе;
  конвертер 250 МВт и квантовый кодировщик 1000 МВт дополнительно сверены с
  Official Satisfactory Wiki. Пиковая мощность каждого рецепта задаётся отдельно.
  Сама кривая UCurveFloat из установленной игры не извлечена.
- Русские названия взяты из `ru.json`. Тематические группы заданы вручную:
  точное совпадение с группами и порядком меню игры **не проверено**.
  Поэтому общий `provenance.verified` остаётся `false`, несмотря на сверенные поля.
  Исследование официальных Headers установило причину: Docs не экспортирует
  `mCategory`, `mOverriddenCategory` и классы `FGItemCategory` с заголовками/порядком.
  `mSubCategories` в заголовке относится к меню строительства зданий.
  При этом **внутри групп применён игровой `mManufacturingMenuPriority`** для всех
  276 рецептов; при равенстве используется русский алфавит, без аттестации в игре.
  Подробности и недостающие сведения перечислены в `source/menu-evidence.json`.
- Скважины с общим компенсатором давления не представлены независимыми узлами.
  Азот можно задать внешним потоком; энергия его получения остаётся за границей.
- Утилизация доступна только твёрдым предметам с положительными игровыми
  `mResourceSinkPoints`; жидкости и радиоактивные отходы не исчезают.
- 162 исходные иконки занимают около 3,35 МБ. У биохимического скульптора
  и утилизатора нет иконки в закреплённом upstream; UI использует свой fallback.

## P1: стоимость строительства и прогресс мира

`scripts/import-game-data.mjs` вызывает `scripts/import-p1-game-data.mjs` и
генерирует `catalog.json`, `audit-report.json` и `progression.json` без сети.
Иконки не меняются. Источники — закреплённые `source/Docs-en-US.json.gz` и
`source/Docs-ru.json.gz`, Steam build **24656030**, дата Docs **2026-08-15**,
дата импорта **2026-09-06**. SHA256 и происхождение повторяются в отчётах P1;
новые внешние данные или непроверенные выгрузки assets не добавлены.

### Стоимость строительства (F01)

- `Building.buildCost` заполнен для **11/11** производственных зданий и **1/1** Sink.
- `Miner.buildCost` заполнен для **5/5** добытчиков; все ингредиенты уже есть
  среди 152 предметов каталога.
- Значение — `Ingredient[]`, количество предметов для **одной новой машины**.
  Это не стоимость апгрейда и не расход материалов в минуту. Переносные буры
  сохранены отдельным материалом; их изготовление не разворачивается рекурсивно.
- Исходник — `FGRecipe.mIngredients` при `mProducedIn=BP_BuildGun_C` и одном
  `FGBuildingDescriptor` в `mProduct` с количеством 1. Сопоставление проверяет
  именование `Build_/Desc_` и точное совпадение английского имени машины с
  build recipe. `mBuildableClass` не экспортирован: прямой asset-pointer не
  объявляется проверенным. Неоднозначное сопоставление останавливает импорт.
- `Recipe_SmelterMk1_C` — **Foundry**, а `Recipe_SmelterBasicMk1_C` — **Smelter**.
  Нельзя получать стоимость заменой префикса имени класса рецепта.
- `audit-report.json.buildCosts.entries` содержит всю цепочку
  stable ID → build class → descriptor → recipe path → исходные/нормализованные
  ингредиенты. Строительные рецепты остаются вне производственной LP-модели.
- Ленты, трубы, провода, фундаменты, энергомодули и усилители не входят в
  стоимость самой машины. Длины/геометрия фабрики не оценивались.

### Открытия (F03): контракт для агента миров

Docs действительно содержит **574 `FGSchematic`** с вложенными `mUnlocks` и
`mSchematicDependencies`. Полный набор сохраняется в
`progression.json.schematics`, включая исходные `rawUnlocks`, `dependencies`,
`cost` (игровые `className`/количества), события и флаги доступа.
Это сведения о схемах, а не утверждение, что все они доступны в игровом меню.

`Catalog.unlocks` содержит **276** схем: **48 HUB** (42 milestone + 6 tutorial),
**106 MAM**, **122 other**. Выбираются несезонные именованные HUB/MAM, схемы с
эффектами на поддержанные сущности и схемы, на которые они ссылаются.
Из них 274 выбраны непосредственно, 2 добавлены при замыкании ссылок.
Имена берутся только из ru Docs; у 9 исходных схем имя пустое, замены не придуманы.
Ещё 17 схем исключены по событиям и 272 не имеют нужных эффектов/ссылок.
Классы `EST_Alternate` остаются `other`; они не приравниваются к обычным MAM-узлам.

| Прямые эффекты схем | Покрытие сущностей каталога |
| --- | ---: |
| Производственные рецепты | 276/276 |
| Производственные здания и Sink | 12/12 |
| Добытчики | 5/5 |
| Ленты | 6/6 |
| Трубы | 2/2 |
| Разгон | `Research_PowerSlugs_2_C`, «Разгон производства» |

`id` — исходный `ClassName`, независимый от языка. `recipeIds`, `buildingIds`,
`beltIds`, `pipeIds` — стабильные ID каталога. Строительные открытия получены из
`BP_UnlockRecipe_C.mRecipes` через продукт build recipe. `kind` выводится из
`mType`, `tier` буквально соответствует `mTechTier`, `overclock` — наличию
`BP_UnlockBuildOverclock_C`. Наличие записи не означает, что схема куплена.

В `Catalog.unlocks` и progression опубликованы поля `minerIds?: string[]`,
`schematicIds?: string[]`, `prerequisiteGroups?: string[][]`,
`prerequisitesKnown?: boolean`. Общий domain меняет владелец задачи.
`minerIds` ссылается на `Catalog.miners`; `buildingIds` по-прежнему содержит
только `Catalog.buildings`. Потребитель может объединять их в общем списке
доступных машин мира и проверять добытчик каждого node-source.
`schematicIds` сохраняет прямые ссылки `BP_UnlockSchematic_C`:
например, `Schematic_5-1_C` ссылается на `Schematic_5-1-1_C` с остаточными
нефтяными рецептами. Импорт не разворачивает дочерние эффекты в родителя.
Все **15** ссылок разрешаются внутри `Catalog.unlocks`: список схем транзитивно
замкнут по children, включая несколько уровней и циклы. При отсутствующем
источнике ребёнка, RU-имени или непредставимых сезонных условиях импорт
останавливается, не подставляет выдуманную схему и не отбрасывает ссылку молча.
Агент миров должен вычислять замыкание выбранных игроком схем по `schematicIds`
с множеством посещённых ID; наличие схемы в каталоге само по себе не открывает её.

**Граф требований неполон.** В закреплённых Docs нет `FGResearchTree` и графа
ветвей MAM; проверенные отдельные экспорты этих assets в `source/` не предоставлены.
`mTechTier=3` у исследования MAM не доказывает его место/зависимости в ветке.
`prerequisiteIds` содержит только явно обязательные purchased dependencies:
AND либо одиночную ссылку. OR нельзя превращать в AND: у
`CustomizerUnlock_PipelineSwatch_C` нужны `Schematic_3-1_C` **или**
`Schematic_2-5_C`. **Контракт `prerequisiteGroups`: AND между группами, OR внутри**:

```ts
// Куплены A и B (mRequireAllSchematicsToBePurchased=True):
prerequisiteGroups: [['A'], ['B']]
// Куплена A или B (mRequireAllSchematicsToBePurchased=False):
prerequisiteGroups: [['A', 'B']]
```

`prerequisiteGroups` содержит также одиночные группы для `prerequisiteIds`:
потребителю нового контракта достаточно групп для явно экспортированных
purchased-условий. В текущем выбранном наборе у схем не более одного исходного
dependency-объекта. Импорт не угадывает оператор между несколькими объектами;
при таком источнике или game-phase условии поле `prerequisiteGroups` отсутствует,
а исходные условия остаются в `dependencies`. `coverage.unprojectedDependencies`
показывает именно такие потери; OR теперь представим без потерь.

`prerequisiteGroups: []` означает только отсутствие экспортированных
purchased-условий. **`prerequisitesKnown=false` у всех 276 схем**: поле означает
полноту всех условий доступности, а не успешное преобразование Docs.
Для MAM неизвестен граф ветви; для остальных схем полнота внешних условий
тоже не установлена. Причины сохранены в
`progression.schematics[].prerequisitesUnknownReasons`.
Ни непустая группа, ни пустой массив не доказывают полного знания доступности;
`coverage.prerequisitesComplete=false`.
В полном исходнике есть ссылки на отсутствующие `Research_Caterium_6_1_C` и
`Schematic_6-4_C`; их имена/эффекты не выдуманы. В выбранном `Catalog.unlocks`
все `prerequisiteIds` разрешаются.

Потребитель может применять прямые эффекты явно отмеченной игроком купленной
схемы и объяснять источник открытия. Нельзя автоматически открывать весь tier,
считать пустые prerequisites доказанным доступом, автоматически выдавать все
альтернативы или объявлять восстановленным полный граф прохождения.

Проверки: catalog-тесты сверяют все 17 стоимостей с tuple исходного Docs,
контрольные Smelter/Foundry/Sink/Miner, локализацию/эффекты всех выбранных схем,
сохранение всех 574 исходных наборов эффектов/зависимостей, AND/OR и SHA256,
miners/children в Catalog.unlocks, многоуровневое замыкание с циклом и отказ при
отсутствующем ребёнке. Последний прогон: **17/17 catalog-тестов — PASS**.
Общий typecheck зависит от готовности параллельных изменений domain/world/UI.
