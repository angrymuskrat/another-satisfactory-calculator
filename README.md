# another-satisfactory-calculator

Персональный русскоязычный калькулятор Satisfactory. React/Vite frontend,
HiGHS в Web Worker и Fastify/SQLite для аккаунтов, миров и фабрик.

В разделе «Рецепты» доступна [быстрая настройка по прогрессу](docs/recipe-progress.md):
фазы и этапы HUB, независимый MAM, альтернативы из дисков, замена/добавление
набора с предпросмотром, совместимые фильтры и сортировка от ранних рецептов.

В рассчитанном плане → «Построить» доступны [схемы цепочки](docs/construction-schematics.md)
по типам зданий и по отдельным машинам: частоты, энергия, входы/выходы и
условные распределительные блоки с расходами и долями ветвей. Есть масштаб,
полный экран и страницы крупных фабрик. Подробная плоская разводка со всеми
устройствами транспорта описана как следующий этап.

## Запуск

Нужны Node.js 24+ и pnpm. Из корня проекта:

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

Frontend: http://127.0.0.1:5173, API: http://127.0.0.1:3001.
Для уже установленного проекта без package manager: `node scripts/dev.mjs`.

Готовая сборка:

```powershell
pnpm build
pnpm start
```

Сервер раздаёт frontend и API на порту 3001. Порт меняется через `PORT`,
файл базы — через `DATABASE_PATH`; по умолчанию `.data/users.sqlite`.
Настройки cookies и API описаны в [apps/api/README.md](apps/api/README.md).

## Docker Compose

Нужен Docker Engine с Compose v2 (на Windows — Docker Desktop с Linux containers).
Node.js и pnpm на хосте не нужны. Из корня проекта:

```powershell
Copy-Item .env.example .env
# Отредактируйте .env под свой способ доступа.
docker compose up --build -d
docker compose ps
docker compose logs -f app
```

В Linux/macOS вместо `Copy-Item` используйте `cp .env.example .env`.
По умолчанию приложение доступно на http://127.0.0.1:3001.
Compose собирает frontend, worker/HiGHS и запускает API, который раздаёт сборку.
Сборка включает проверку TypeScript; тесты не запускаются автоматически.
Сервер работает от пользователя `node`, проверка здоровья обращается к `/api/session`.

В [.env.example](.env.example) перечислены настройки с комментариями:

| Переменная | Что указать |
| --- | --- |
| `BIND_ADDRESS` | `127.0.0.1` для локального доступа; `0.0.0.0` или IP хоста для доступа из сети |
| `PORT` | Свободный внешний порт, по умолчанию `3001` |
| `SECURE_COOKIES` | `false` для HTTP, обязательно `true` при доступе через HTTPS |

Для HTTPS нужен внешний reverse proxy с сертификатом и сохранением исходного
`Host`, включая нестандартный порт. Контейнер обслуживает HTTP на порту 3001;
`SECURE_COOKIES=true` включает Secure cookies и проверку HTTPS Origin.
API-ключи и заранее заданный пароль администратора не нужны: аккаунт создаётся
через интерфейс. `.env` не коммитится и не попадает в образ. Этот файл читает
Compose; для `pnpm start` переменные нужно передать через окружение процесса.

SQLite хранится в именованном томе `app-data`, путь внутри контейнера —
`/app/.data/users.sqlite`. Локальная `.data` не импортируется автоматически.
`docker compose down` сохраняет данные; `docker compose down -v` удаляет том
вместе с аккаунтами и профилями. Для обновления выполните
`docker compose up --build -d` повторно. После изменения `.env` достаточно
`docker compose up -d`. При смене каталога проекта или имени Compose-проекта
будет использован другой том; сохраняйте имя проекта для доступа к прежним данным.

## Возможности

- Максимум выпуска или заданный заказ. Для нескольких продуктов — пропорции,
  приоритеты либо веса; у каждого продукта можно задать минимум и максимум.
- Ограничения источников, месторождений, транспорта, средней и максимальной
  мощности с резервом; предел физического количества зданий каждого типа.
- «Цели и ограничения» и «Результаты» открываются отдельно в навигации.
  Результаты и схемы используют доступную ширину; полный экран сохранён.
- Единственная цель интерфейса — «Ровная нагрузка: здания → энергия → сырьё».
  Альтернативные рецепты сравниваются по всей цепочке в разделе рецептов;
  проверки расширения и перестройки находятся в настройках.
- Повторный расчёт проверяет пользу конкретного источника, увеличения мощности,
  открытия рецепта/здания или утилизации, в том числе совместных изменений.
- Каталог с поиском «производит / использует / везде», сворачиваемыми группами,
  величинами за цикл, в минуту и на единицу выбранного выхода. Частота карточек
  берётся из технологий и показана справочно, без отдельного поля ввода.
- «Построить»: число машин, заданная или подобранная частота, активные и средние потоки,
  мощность, материалы зданий, копирование чисел и локальные отметки строительства.
- Мир хранит прогресс HUB/MAM и ручные открытия; несколько фабрик наследуют его
  через снимки. Изменения прогресса сначала показываются для просмотра.
- Справочник MAM и фаз HUB показывает связанные исследования для закрытого
  рецепта, варианты ИЛИ и неизвестные связи; завершение отмечается вручную.
- Справочник MAM и фаз HUB показывает связанные исследования для закрытого
  рецепта, варианты ИЛИ и неизвестные связи; завершение отмечается вручную.
- Гостевые черновики, JSON, аккаунты и сохранённые профили остаются доступны.
  Фабрики сохраняются явно в разделе «Миры и фабрики»; импорт пространства добавляет
  копии с новыми ID. По согласованию старые планы с целями power/resources/buildings
  удаляются при загрузке вместе с соответствующими фабриками. Миры, аккаунты и
  планы smooth-power сохраняются. Повторный импорт прежней цели отклоняется явно.

## Возможности P2

- Расширение существующего производства: закреплённые и свободные линии,
  сравнение «оставить / добавить / перестроить», отдельная ведомость новых зданий.
- Партии для лифта/склада: количество, запас, срок и расчёт нужного выпуска.
- Конечный бюджет Somersloops и скважины с общим компенсатором;
  материалы компенсатора и всех настроенных спутников включены в ведомость.
- Заметки и резерв источников, явная стоимость энергии импорта, отгрузки побочных
  продуктов. Общие узлы мира распределяются между фабриками конечными квотами.

## Границы расчёта

В целях энергии/сырья/зданий частоты заданы пользователем. Средние потоки моделируют долю времени работы;
75% времени работы при 100% частоте не заменяется частотой 75%. Пиковая оценка
консервативна, накопители, фазы циклов, standby и запуск не моделируются.
Положительные границы продуктов и заданный выпуск поддерживаются от 0,000001
в минуту; меньший масштаб отклоняется с объяснением. При численном сбое
физических количеств выводится ошибка, а не ложное утверждение о невыполнимости.
Неизвестная энергия внешних поставок исключена; явно заданная стоимость учтена.
«Ровная нагрузка» сначала минимизирует число машин, затем подбирает частоты
от 1% до заданного предела для непрерывного выпуска и экономии энергии.
Этот вариант выбран по умолчанию для новых планов и сброса. В сохранённых
планах и черновиках остаётся выбранная цель.
Закреплённые линии сохраняются. Нелинейная энергия оптимизируется приближённо
с консервативной оценкой; точные MW проверяются, статус — «Допустимое приближение».
Подробнее: [автоподбор частот](docs/power-smoothing.md).
Динамика запуска остаётся вне модели. Названия и состав
категорий подтверждены игровыми assets; порядок категорий с отсутствующим
приоритетом и равными приоритетами дополняется русским алфавитом.
Плавильня поддерживает один усилитель по общим настройкам игровой подсистемы.
Квоты разных черновиков проверяются
совместно при сохранении пространства. Партия оценивает время после выхода на режим.

Статус проверок и ограничений: [docs/STATUS.md](docs/STATUS.md).
Происхождение данных и воспроизводимый импорт:
[packages/game-data/README.md](packages/game-data/README.md).

## Проверки

```powershell
pnpm test
pnpm typecheck
pnpm build
pnpm test:ui
```

Для UI предварительно запустите приложение. По умолчанию тесты используют
порт 5173 и установленный Chrome. Для готовой сборки задайте
`$env:PLAYWRIGHT_BASE_URL='http://127.0.0.1:3001'` перед `pnpm test:ui`.
Браузерные тесты создают технические аккаунты; проверочную базу можно отделить
через `DATABASE_PATH` при запуске сервера. Скриншоты и traces лежат в `output/`.

Правила разработки: [AGENTS.md](AGENTS.md). Данные игры и сторонний код:
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
