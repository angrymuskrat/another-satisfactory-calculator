# another-satisfactory-calculator

Персональный русскоязычный калькулятор Satisfactory. React/Vite frontend,
HiGHS в Web Worker и Fastify/SQLite для аккаунтов, миров и фабрик.

На экране «Цели и ограничения» откройте **«Рассчитать по продукту»**, выберите
предмет и введите выпуск в минуту. Быстрый заказ использует обычные рецепты,
внешнее сырьё без лимита и частоту до 100%. Для 20 железных пластин в минуту
он показывает расход 30 железной руды в минуту и предлагает начать с плавильни.
«Расширенные настройки» открывают тот же заказ для изменения поставок и технологий.

Кнопка **«Поделиться заказом»** создаёт ссылку с версией каталога, целями,
рецептами и ограничениями. Получатель открывает её без аккаунта и пересчитывает
снимок у себя. Изменённый заказ можно передать новой ссылкой или экспортировать
в JSON. Кнопка «Вернуться к своей фабрике» открывает личный план.

В разделе «Рецепты» доступна [быстрая настройка по прогрессу](docs/recipe-progress.md):
фазы и этапы HUB, независимый MAM, альтернативы из дисков, замена/добавление
набора с предпросмотром, совместимые фильтры и сортировка от ранних рецептов.

В рассчитанном плане → «Построить» доступны [схемы цепочки](docs/construction-schematics.md)
по типам зданий и по отдельным машинам: частоты, энергия, входы/выходы,
масштаб, полный экран и страницы крупных фабрик. При включённом учёте
разделителей показывается проверенная топология конвейеров с каждым устройством
и физической лентой. Геометрическое размещение в игровом мире не рассчитывается.

В «Цели и ограничения» учёт схем разделителей и соединителей включается
отдельно; максимальная глубина 1–4 считает оба вида устройств по самому
длинному пути. По умолчанию учёт выключен, запомненная глубина — 4.
Выключение сохраняет выбранную глубину и возвращает прежний расчёт.
Самостоятельный раздел «Схемы разделителей» доступен в обоих состояниях:
полные наборы долей, фильтры, проверенные конструкции и пробная подача.
Для глубин 1–3 перебор завершён: 3, 19 и 1355 распределений, включая прямую
ленту. Глубина 4 генерируется порциями; её полный размер и завершимость на
доступной памяти пока не подтверждены. Интерфейс явно показывает неполноту.

## Запуск

Нужны Node.js 24+ и pnpm. Из корня проекта:

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

Frontend: http://127.0.0.1:5173, API: http://127.0.0.1:3001.
Для уже установленного проекта без package manager: `node scripts/dev.mjs`.

Готовая сборка:

```powershell
pnpm build
pnpm start
```

Сервер раздаёт frontend и API на порту 3001. Порт меняется через `PORT`,
файл базы — через `DATABASE_PATH`; по умолчанию `.data/users.sqlite`.
Настройки cookies и API описаны в [apps/api/README.md](apps/api/README.md).

## Docker Compose

Нужен Docker Engine с Compose v2 (на Windows — Docker Desktop с Linux containers).
Node.js и pnpm на хосте не нужны. Из корня проекта:

```powershell
Copy-Item .env.example .env
# Отредактируйте .env под свой способ доступа.
docker compose up --build -d
docker compose ps
docker compose logs -f app
```

В Linux/macOS вместо `Copy-Item` используйте `cp .env.example .env`.
По умолчанию приложение доступно на http://127.0.0.1:3001.
Compose собирает frontend, worker/HiGHS и запускает API, который раздаёт сборку.
Сборка включает проверку TypeScript; тесты не запускаются автоматически.
Сервер работает от пользователя `node`, проверка здоровья обращается к `/api/session`.

В [.env.example](.env.example) перечислены настройки с комментариями:

| Переменная | Что указать |
| --- | --- |
| `BIND_ADDRESS` | `127.0.0.1` для локального доступа; `0.0.0.0` или IP хоста для доступа из сети |
| `PORT` | Свободный внешний порт, по умолчанию `3001` |
| `SECURE_COOKIES` | `false` для HTTP, обязательно `true` при доступе через HTTPS |

Для HTTPS нужен внешний reverse proxy с сертификатом и сохранением исходного
`Host`, включая нестандартный порт. Контейнер обслуживает HTTP на порту 3001;
`SECURE_COOKIES=true` включает Secure cookies и проверку HTTPS Origin.
API-ключи и заранее заданный пароль администратора не нужны: аккаунт создаётся
через интерфейс. `.env` не коммитится и не попадает в образ. Этот файл читает
Compose; для `pnpm start` переменные нужно передать через окружение процесса.

SQLite хранится в именованном томе `app-data`, путь внутри контейнера —
`/app/.data/users.sqlite`. Локальная `.data` не импортируется автоматически.
`docker compose down` сохраняет данные; `docker compose down -v` удаляет том
вместе с аккаунтами и профилями. Для обновления выполните
`docker compose up --build -d` повторно. После изменения `.env` достаточно
`docker compose up -d`. При смене каталога проекта или имени Compose-проекта
будет использован другой том; сохраняйте имя проекта для доступа к прежним данным.

## Возможности

- Максимум выпуска или заданный заказ. Для нескольких продуктов — пропорции,
  приоритеты либо веса; у каждого продукта можно задать минимум и максимум.
- Ограничения источников, месторождений, транспорта, средней и максимальной
  мощности с резервом; предел физического количества зданий каждого типа.
- «Цели и ограничения» и «Результаты» открываются отдельно в навигации.
  Результаты и схемы используют доступную ширину; полный экран сохранён.
- «Рассчитать» предлагает максимальный выпуск, экономию энергии и экономию
  редкого сырья с подбором частот; совпавшие варианты объединяются. В «Подборе вариантов» задаются потеря выпуска для экономии (по умолчанию
  10%) и дополнительные машины относительно компактной фабрики (по умолчанию 0).
  «Использовать вариант» открывает его точную схему без повторного решения;
  одинаковые варианты объединяются, после завершения подбора первый решённый
  вариант показывается сразу. Над результатом можно переключить показанный вариант, не меняя план;
  в план его записывает «Принять вариант». Заданный заказ и партия не уменьшаются.
  Альтернативные рецепты сравниваются по всей цепочке в разделе рецептов;
  проверки расширения и перестройки находятся в настройках.
- Веса сырья по умолчанию — «по редкости карты» (запасы узлов по Official
  Satisfactory Wiki, не сверены со сборкой); у источника показана доля запаса карты.
- «Что дадут альтернативы» в результатах: каждая выключенная альтернатива,
  производящая предмет цепочки, проверяется полным пересчётом; рейтинг по
  порядку целей плана, кнопка «Разрешить в плане».
- Повторный расчёт проверяет пользу конкретного источника, увеличения мощности,
  открытия рецепта/здания или утилизации, в том числе совместных изменений.
- Каталог с поиском «производит / использует / везде», сворачиваемыми группами,
  величинами за цикл, в минуту и на единицу выбранного выхода. Частота карточек
  берётся из технологий и показана справочно, без отдельного поля ввода.
- Табло результата: цель, «Дальше строим» с кнопкой отметки готовых машин,
  «Построено n / M», энергия и сырьё; под ним раскрываемые разделы.
- «Построить»: число машин, заданная или подобранная частота, активные и средние потоки,
  мощность, материалы зданий, копирование чисел и локальные отметки строительства.
- Мир хранит прогресс HUB/MAM и ручные открытия; несколько фабрик наследуют его
  через снимки. Изменения прогресса сначала показываются для просмотра.
- Справочник MAM и фаз HUB показывает связанные исследования для закрытого
  рецепта, варианты ИЛИ и неизвестные связи; завершение отмечается вручную.
- Справочник MAM и фаз HUB показывает связанные исследования для закрытого
  рецепта, варианты ИЛИ и неизвестные связи; завершение отмечается вручную.
- Гостевые черновики, JSON, аккаунты и сохранённые профили остаются доступны.
  Фабрики сохраняются явно в разделе «Миры и фабрики»; импорт пространства добавляет
  копии с новыми ID. По согласованию старые планы с целями power/resources/buildings
  удаляются при загрузке вместе с соответствующими фабриками. Миры, аккаунты и
  планы smooth-power сохраняются. Повторный импорт прежней цели отклоняется явно.

### От расчёта к строительству

Для крупного заданного заказа или партии калькулятор может показать **«Открыть рабочий план»**, пока продолжается оптимизация. Потоки, целые машины и ограничения такого плана уже проверены. Если следующий критерий не уложился в срок, схемой можно пользоваться и продолжить поиск. [Расчёт ранних вариантов](packages/solver/workingPlans.ts)

Если заданных входов мало, раздел **«Где добавить снабжение»** показывает дополнительный поток и его потребителей. В предпросмотре можно подобрать добытчик и чистоту узла либо указать внешнюю поставку. **«Проверить снабжение»** пересчитывает заказ с предложенными источниками. **«Применить снабжение»** переносит изменения в фабрику. [Предпросмотр источников](apps/web/src/SupplyGaps.tsx)

Отметьте построенные машины в инструкции или на схеме, чтобы увидеть, какие блоки готовы к строительству и чего ждут остальные. Карточки можно перемещать мышью и клавиатурой. Положения и отметки сохраняются в браузере. [Строительная схема](apps/web/src/Schematic.tsx)

В настройках отгрузки можно включить **«Переработать побочные жидкости на месте»**. В результатах сравниваются проверенные способы обращения с остатком при одинаковом выпуске, включая переработку, отгрузку получателю и разрешённую утилизацию твёрдых предметов. Можно увидеть, сколько МВт, оборудования и сырья потребует каждый путь. [Сравнение путей](apps/web/src/ResidueHelp.tsx)

Предложение для среднего этапа игры, ещё не согласованное к реализации.

3. **Простота и логистика:** число разных рецептов, вариант «проще построить»,

4. **Энергия и отзывчивость:** генераторы и топливо для покрытия мощности,
   показ основного варианта до завершения экономичного.

## Границы расчёта

В целях энергии/сырья/зданий частоты заданы пользователем. Средние потоки моделируют долю времени работы;
75% времени работы при 100% частоте не заменяется частотой 75%. Пиковая оценка
консервативна, накопители, фазы циклов, standby и запуск не моделируются.
Положительные границы продуктов и заданный выпуск поддерживаются от 0,000001
в минуту; меньший масштаб отклоняется с объяснением. При численном сбое
физических количеств выводится ошибка, а не ложное утверждение о невыполнимости.
Неизвестная энергия внешних поставок исключена; явно заданная стоимость учтена.
Оба варианта подбирают частоты от 1% до заданного предела для непрерывного
выпуска, где это возможно. Максимальный использует минимум машин;
экономичный минимизирует энергию в конечном бюджете «минимум + добавление».
В профилях и черновиках сохраняются настройки сравнения и выбранного расчёта.
Закреплённые линии сохраняются. Нелинейная энергия оптимизируется приближённо
с консервативной оценкой; точные MW проверяются, статус — «Допустимое приближение».
Подробнее: [автоподбор частот](docs/power-smoothing.md).
При включённом учёте конвейерных схем состав машин и топология ищутся
приближённо с общим сроком: найденный результат проходит независимую проверку,
но глобальные максимум выпуска и минимум машин с логистикой не доказаны.
Уравнения выбранных устройств действуют до целей расчёта; готовые расходы
не округляются. Неуспех неполного поиска обозначается тайм-аутом.
Внешний поток предполагает независимые входные ленты с равной подачей;
разделение поставки до границы фабрики не рассчитывается. Sink для разных
предметов отдельные. Жидкости сохраняют прежнюю модель. Логистические устройства
показываются отдельно от бюджета машин, их материалы пока не включены в ведомость.
Подробнее: [модель конвейерных схем](docs/plans/2026-09-13-splitter-routing-design.md).
Динамика запуска остаётся вне модели. Названия и состав
категорий подтверждены игровыми assets; порядок категорий с отсутствующим
приоритетом и равными приоритетами дополняется русским алфавитом.
Плавильня поддерживает один усилитель по общим настройкам игровой подсистемы.
Квоты разных черновиков проверяются
совместно при сохранении пространства. Партия оценивает время после выхода на режим.

Статус проверок и ограничений: [docs/STATUS.md](docs/STATUS.md).
Происхождение данных и воспроизводимый импорт:
[packages/game-data/README.md](packages/game-data/README.md).

## Проверки

```powershell
pnpm test
pnpm typecheck
pnpm build
pnpm test:ui
```

Для UI предварительно запустите приложение. По умолчанию тесты используют
порт 5173 и установленный Chrome. Для готовой сборки задайте
`$env:PLAYWRIGHT_BASE_URL='http://127.0.0.1:3001'` перед `pnpm test:ui`.
Браузерные тесты создают технические аккаунты; проверочную базу можно отделить
через `DATABASE_PATH` при запуске сервера. Скриншоты и traces лежат в `output/`.

Попиксельная заморозка экранов (`tests/ui/visual-freeze.spec.ts`) проверяет,
что изменение не меняет отрисовку: снимки делятся на участки до 8000 px
по высоте и сравниваются по каждому каналу каждого пикселя. Без
`VISUAL_FREEZE` она пропускается. Тесты запускаются из checkout изменения,
а эталон снимается с сервера базовой сборки: запустите `pnpm build` и
`pnpm start` в отдельной копии базового коммита с другим `PORT`, например
3002, и сборку изменения на 3001. Эталон лежит в `output/visual-freeze/`;
оба запуска — в одном окружении (тот же браузер и шрифты):

```powershell
$env:VISUAL_FREEZE='1'; $env:PLAYWRIGHT_BASE_URL='http://127.0.0.1:3002'; pnpm test:ui visual-freeze --update-snapshots
$env:VISUAL_FREEZE='1'; $env:PLAYWRIGHT_BASE_URL='http://127.0.0.1:3001'; pnpm test:ui visual-freeze
```

Перед сравнением изменения полезно повторить вторую команду против базового
сервера: так видно, что эталон воспроизводится сам с собой. Эталон и сравнение
делайте без перезапуска окружения между ними: после перезапуска Docker Desktop
сглаживание краёв на дробных координатах может отличаться на единицы пикселей.

Правила разработки: [AGENTS.md](AGENTS.md). Данные игры и сторонний код:
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Обзор вариантов по энергии и ресурсам

В режиме «Заданный выпуск» включите «Подобрать компромиссы для заданного выпуска».
Расчёт показывает до 12 вариантов за проход: среднюю/пиковую мощность, число машин
и расход каждого входного ресурса. Выберите вариант, затем уточните суммарные
лимиты ресурсов и пересчитайте; таблица покажет изменения относительно выбора.
«Продолжить поиск» уточняет обзор. Редкость и предварительная минимизация машин
в этом режиме не используются; экономия может потребовать много медленных машин.

«Самообеспечение электричеством» добавляет генераторы и топливную цепочку для угля,
нефти или урана. Генераторы работают на 100%, покрывают локальный пик с резервом;
входы — первичное сырьё, отходы должны перерабатываться или иметь разрешённую

Данные генерации воспроизводятся общей командой `pnpm data:import`.
Та же команда пишет словари названий из игры `packages/game-data/locales/<язык>.json`
(сейчас `ru` и `en`); каталог при этом не меняется.
